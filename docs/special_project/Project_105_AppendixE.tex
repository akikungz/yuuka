\section{การ Deploy และการตั้งค่าสำหรับ Production}
\hspace*{1.3em}
การติดตั้งใช้งานจริงในฉบับปัจจุบันไม่ได้อาศัย Docker Compose production file ชุดเดียวเหมือนตัวอย่างเก่า แต่แยกออกเป็นสองส่วนหลัก คือบริการภายในคลัสเตอร์ที่จัดการด้วย manifest ในรีโพซิทอรี Yuuka และบริการ reverse proxy ภายนอกที่ใช้ Nginx ร่วมกับ Satsuki สำหรับสร้าง configuration อัตโนมัติ

\section{องค์ประกอบของสภาพแวดล้อม Production}
\hspace*{1.3em}
สภาพแวดล้อม production ของระบบสามารถแบ่งเป็นองค์ประกอบสำคัญได้ดังนี้

\begin{mycustomenum2}
    \item \textbf{Application Services ในคลัสเตอร์}
    \begin{mycustomenum2}
        \item Midori สำหรับส่วนติดต่อผู้ใช้
        \item Momoi สำหรับ API และ business logic
        \item Yuzu สำหรับ queue worker
        \item PostgreSQL, Redis และ RustFS สำหรับบริการสนับสนุน
        \item Prometheus, Grafana, Loki, Jaeger และ OTEL Collector สำหรับ observability
    \end{mycustomenum2}
    \item \textbf{External Reverse Proxy Host}
    \begin{mycustomenum2}
        \item Nginx ทำหน้าที่เป็น reverse proxy หน้าด่าน
        \item Satsuki ทำหน้าที่สร้างไฟล์ stream/http configuration และ \textbf{authorized\_keys}
        \item บริการส่วนนี้เชื่อมต่อกับ PostgreSQL โดยตรงเพื่อใช้ LISTEN/NOTIFY
    \end{mycustomenum2}
\end{mycustomenum2}

\section{การตั้งค่า Environment Variables สำหรับ Production}
\hspace*{1.3em}
การตั้งค่า environment ควรยึดตามไฟล์ตัวอย่างของแต่ละรีโพซิทอรีเป็นหลัก โดยค่าที่สำคัญมีดังนี้

\begin{mycustomenum2}
    \item \textbf{Momoi}
    \begin{mycustomenum2}
        \item \textbf{PORT=3000}
        \item \textbf{DATABASE\_URL} สำหรับ PostgreSQL
        \item \textbf{REDIS\_URL} สำหรับ Redis
        \item \textbf{BETTER\_AUTH\_URL} สำหรับ callback และ session
        \item กลุ่มค่าของ S3-compatible storage เช่น \textbf{S3\_ENDPOINT}, \textbf{S3\_ACCESS\_KEY\_ID}, \textbf{S3\_SECRET\_ACCESS\_KEY}
    \end{mycustomenum2}
    \item \textbf{Yuzu}
    \begin{mycustomenum2}
        \item \textbf{PVE\_API\_URL}, \textbf{PVE\_API\_TOKEN\_ID}, \textbf{PVE\_API\_TOKEN\_SECRET}
        \item \textbf{DATABASE\_URL} และ \textbf{REDIS\_URL}
        \item \textbf{YUZU\_PROVISION\_CONCURRENCY}, \textbf{YUZU\_DEPROVISION\_CONCURRENCY}, \textbf{YUZU\_TOGGLE\_STATUS\_CONCURRENCY}
        \item ค่าที่ใช้จูน resource locks เช่น \textbf{YUZU\_RESOURCE\_LOCK\_TTL\_MILLIS}
    \end{mycustomenum2}
    \item \textbf{Satsuki}
    \begin{mycustomenum2}
        \item \textbf{DATABASE\_URL}
        \item \textbf{PROXY\_DOMAIN\_SUFFIX}
        \item \textbf{NGINX\_STREAM\_CONF\_PATH}, \textbf{NGINX\_HTTP\_CONF\_PATH}
        \item \textbf{NGINX\_RELOAD\_COMMAND}
        \item \textbf{BASTION\_AUTHORIZED\_KEYS\_PATH}
    \end{mycustomenum2}
\end{mycustomenum2}

\section{การตั้งค่า Reverse Proxy และ TLS}
\hspace*{1.3em}
ในฉบับปัจจุบัน reverse proxy สำหรับ HTTP และ TCP ไม่ได้ถูกดูแลด้วยการแก้ไฟล์ Nginx ด้วยมือทั้งหมด แต่ใช้ Satsuki เป็นผู้สร้างไฟล์ configuration จากข้อมูลในฐานข้อมูล จากนั้นสั่ง reload Nginx อัตโนมัติเมื่อเกิดการเปลี่ยนแปลง

\begin{mycustomenum2}
    \item HTTP reverse proxy ใช้สำหรับเส้นทางเว็บและ API หลัก
    \item TCP/TLS stream proxy ใช้สำหรับการเข้าถึงบริการใน VM ผ่านชื่อโฮสต์แบบ \textbf{p\{port\}-\{instance-hostname\}.\{domain\}}
    \item หากต้องการ tunnel ฝั่งผู้ใช้ สามารถใช้ \textbf{ncat}, \textbf{socat} หรือ \textbf{stunnel} ร่วมกับปลายทางที่ Nginx สร้างไว้
\end{mycustomenum2}

\section{การตรวจสอบและบำรุงรักษาระบบ}
\hspace*{1.3em}
การตรวจสอบระบบใน production ควรครอบคลุมทั้งฝั่งคลัสเตอร์และฝั่งเครื่อง Nginx ภายนอก

\begin{mycustomenum2}
    \item ตรวจสอบ pod, deployment และ service ของ Midori, Momoi และ Yuzu ในคลัสเตอร์
    \item ตรวจสอบ PostgreSQL, Redis และ RustFS ว่าพร้อมใช้งาน
    \item ตรวจสอบ queue depth, log และ metrics ของ Yuzu
    \item ตรวจสอบ log ของ Satsuki, ไฟล์ Nginx configuration ที่ถูก generate และสถานะการ reload ของ Nginx
    \item ตรวจสอบ dashboards และ traces ใน Prometheus, Grafana และ Jaeger
\end{mycustomenum2}

\section{การแก้ไขปัญหาใน Production}
\hspace*{1.3em}
แนวทางการแก้ปัญหาที่พบบ่อยสามารถสรุปได้ดังนี้

\begin{mycustomenum2}
    \item \textbf{Service ภายในคลัสเตอร์ไม่ตอบสนอง}
    \begin{mycustomenum2}
        \item ตรวจสอบสถานะ pod และ logs ของ service ที่เกี่ยวข้อง
        \item ตรวจสอบการเชื่อมต่อกับ PostgreSQL และ Redis
        \item ตรวจสอบ resource limits และ readiness/liveness probes
    \end{mycustomenum2}
    \item \textbf{Yuzu ไม่ประมวลผลงาน}
    \begin{mycustomenum2}
        \item ตรวจสอบ queue state บน Redis
        \item ตรวจสอบค่า concurrency และ resource lock ที่เกี่ยวข้องกับ \textbf{instanceId} หรือ \textbf{VMID}
        \item ตรวจสอบการเชื่อมต่อและสิทธิ์ของ Proxmox API token
    \end{mycustomenum2}
    \item \textbf{Reverse proxy หรือ SSH access ใช้งานไม่ได้}
    \begin{mycustomenum2}
        \item ตรวจสอบไฟล์ที่ Satsuki สร้างบนเครื่อง Nginx ภายนอก
        \item ตรวจสอบ LISTEN/NOTIFY และการเชื่อมต่อฐานข้อมูลของ Satsuki
        \item ตรวจสอบ certificate, Nginx reload และสิทธิ์ของไฟล์ \textbf{authorized\_keys}
    \end{mycustomenum2}
\end{mycustomenum2}
