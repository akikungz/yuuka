\section{ภาพรวมของโครงสร้างแบบหลายรีโพซิทอรี}
\hspace*{1.3em}
โครงงาน Cloud-Based Platform ในปัจจุบันไม่ได้จัดเก็บซอร์สโค้ดไว้ในรีโพซิทอรีเดียว แต่แยกออกเป็นหลายรีโพซิทอรีตามขอบเขตความรับผิดชอบของบริการ เพื่อให้พัฒนา ทดสอบ และติดตั้งใช้งานได้ยืดหยุ่นมากขึ้น รีโพซิทอรีที่เกี่ยวข้องกับระบบในฉบับปัจจุบันประกอบด้วย Midori, Momoi, Yuzu, Satsuki และ Yuuka

\begin{mycustomenum2}
    \item \textbf{Midori} เป็นส่วนติดต่อผู้ใช้ พัฒนาด้วย Next.js และ React
    \item \textbf{Momoi} เป็นบริการ API หลัก พัฒนาด้วย Bun, Elysia.js และ Prisma
    \item \textbf{Yuzu} เป็น worker service สำหรับงาน VM lifecycle และ queue processing
    \item \textbf{Satsuki} เป็นบริการ automation สำหรับ reverse proxy และ SSH access บนเครื่อง Nginx ภายนอก
    \item \textbf{Yuuka} เป็นรีโพซิทอรีสำหรับ manifests, Docker Compose, observability และเอกสารที่เกี่ยวข้องกับ deployment
\end{mycustomenum2}

\section{ข้อกำหนดของระบบ}
\hspace*{1.3em}
ก่อนเริ่มต้นใช้งาน ควรติดตั้งซอฟต์แวร์พื้นฐานดังนี้

\begin{mycustomenum2}
    \item Bun เวอร์ชัน 1.3 หรือสูงกว่า
    \item Docker และ Docker Compose Plugin
    \item Git สำหรับโคลนแต่ละรีโพซิทอรี
    \item PostgreSQL และ Redis ในกรณีที่ไม่ใช้งานผ่าน Docker Compose ของ Yuuka
    \item Proxmox VE สำหรับการทดสอบงานที่เกี่ยวข้องกับการจัดการ VM จริง
\end{mycustomenum2}

\section{การเตรียมไฟล์ Environment}
\hspace*{1.3em}
ค่ากำหนดของระบบถูกแยกเก็บตามรีโพซิทอรี และในรีโพซิทอรี Yuuka ยังมีไฟล์ตัวอย่างในโฟลเดอร์ \textbf{docs/env} เพื่อใช้ประกอบเอกสารและ onboarding ผู้พัฒนาควรใช้ไฟล์ตัวอย่างจากรีโพซิทอรีจริงของแต่ละบริการเป็นหลัก แล้วตรวจสอบให้ค่าต่อไปนี้สอดคล้องกัน

\begin{mycustomenum2}
    \item PostgreSQL connection string
    \item Redis URL
    \item S3-compatible storage endpoint และ credentials
    \item API endpoint ที่ Midori เรียกใช้งาน
    \item Proxmox VE credentials ของ Yuzu
    \item path และ reload command ของ Satsuki บนเครื่อง Nginx ภายนอก
\end{mycustomenum2}

\section{ข้อสังเกตสำหรับการพัฒนาใน workspace เดียวกัน}
\hspace*{1.3em}
แม้ระบบจะเป็นหลายรีโพซิทอรี แต่สามารถเปิดใช้งานร่วมกันใน workspace เดียวของโปรแกรมพัฒนาได้ ซึ่งช่วยให้ค้นหาโค้ด อ้างอิงไฟล์ และติดตามการไหลของข้อมูลระหว่างบริการได้สะดวกขึ้น โดยเฉพาะเมื่อต้องตรวจสอบความสอดคล้องของ schema, API contract, queue names, environment variables และ deployment manifests
